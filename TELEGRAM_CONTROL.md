# Telegram: підготовка команд і блокування фізичного запису

Поточний режим для INGECON SUN 100TL описано в [MODBUS.md](MODBUS.md).
Історичні команди непідтверджені. **Фізичний запис заблоковано на backend**
через `modbus_safety.py`, незалежно від ролі, конфігурації бота,
`MODBUS_WRITES_ENABLED`, `allow_write=True` або тестової панелі.

Глобальна карта Holding Registers зберігається в одному приватному
`instance/production/modbus.json` і спільна для всіх інверторів, вебу й бота.
Редагування: Налаштування → Modbus. Немає параметра ввімкнення записів
чи можливості позначити карту перевіреною через цю форму.

Історичні значення: увімкнення HR1000=6, вимкнення HR1000=5,
ліміт HR46=1–100, читання ліміту HR1001, причини HR47.
Адреси не зміщуються автоматично. Значення HR1001/47 повертаються як сирі;
офіційна карта FC04 зберігається окремо.

Telegram зберігає прив’язку, ролі, вибір інвертора/групи, двоетапне підтвердження,
строк 120 секунд, аудит та результати за пристроями. У цьому режимі результат
керування — «заблоковано»; статуси й сповіщення продовжують працювати з SQLite.
Старі підтвердження не переживають зміну глобальної конфігурації.

Попередній приватний `INGECON_TELEGRAM_CONTROL_CONFIG` може залишатися для
сумісності та переліку дозволених ID/IP, але не вмикає записів. Його старі
адреси/значення команд не замінюють глобальну карту. Наявні файли не видаляються
й не переписуються цим оновленням. Не застосовуйте старі інструкції активації
за допомогою самого лише `enabled:true`.

Перевірка старої політики офлайн, від користувача служби:

```bash
.venv/bin/python telegram_bot.py check-control-config --file /opt/ingecon-control/instance/telegram/control.json
```

Команда не підключається до SQLite, Telegram або інверторів і прямо показує
backend-блокування. Створювати цей файл для поточного режиму не потрібно.

Подальше фізичне керування потребуватиме окремо погодженої активації:
перевіреної карти конкретного обладнання/прошивки, прив’язки дозволу до
відбитка глобальної конфігурації та окремих дозволів для команд. Зміна карти
має відкликати дозвіл. Поточний UI не містить такого перемикача.

Усі позитивні write-тести працюють виключно з `FakeModbusTcpClient`;
тестова фікстура явно знімає міжблокування лише в процесі pytest,
де заблоковані IP-сокети та DNS. Окремі тести перевіряють справжнє
міжблокування без цього перевизначення. Production-БД, користувачів,
Telegram-прив’язки, токен, SECRET_KEY і systemd під час підготовки не змінено.
