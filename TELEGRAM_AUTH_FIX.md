# Збереження Telegram-авторизації

## Причина

Вебсесії й Telegram-прив’язка перевіряють одну `User.session_version`. Старий
`POST /logout` збільшував її, але залишав попередню `TelegramLink.user_version`.
Бот правильно відхиляв таку прив’язку як відкликану. Вихід перед входом іншого
вебкористувача відтворював проблему. Перезапуск бота не змінює запис, тому
невідповідність залишалась і після нього. У startup/recover немає видалення прив’язок.

## Виправлення

Вебвихід однією SQLite-транзакцією:

1. Умовно збільшує версію користувача, звіряючи її з версією автентифікованої cookie.
2. Переводить на нову версію лише його чинну Telegram-прив’язку й чинний код.
3. Фіксує обидві зміни та очищає вебсесію.

Скопійовані cookie й інші старі вебсесії відкликані, Telegram залишається доступним.
ID, дата прив’язки, груповий фільтр, сповіщення та курсор подій збережені. Код має
той самий digest і строк 5 хвилин; вихід не подовжує його. Вхід іншого облікового
запису не змінює чужих Telegram-записів. Штатний restart використовує той самий
production SQLite та той самий токен; додаткового бота не потрібно.

Зміна пароля/версії адміністратором, деактивація, видалення та явне відкликання
й далі блокують доступ. Відкликані записи не переводяться на нову версію.
Умовний UPDATE захищає від конкурентної зміни пароля, rollback — від часткової
помилки. Підготовлені підтвердження команд зі старою версією не виконуються;
користувач має підготувати нову команду. Карта Modbus, дозволи й виконання команд
не змінені, фізичних команд під час перевірок немає.
Бот читає прив’язку й користувача одним JOIN із поновленням ORM-кешу: дві версії
походять з одного знімка SQLite, без проміжного стану під час конкурентного logout.

## Якщо авторизація вже втрачена

У **Налаштування → Telegram** з’являється попередження про недійсну прив’язку.
Потрібна одноразова повторна прив’язка:

1. Натиснути **Відкликати прив’язку та коди**.
2. Натиснути **Створити код**.
3. Надіслати `/start КОД` своєму боту в приватному чаті протягом 5 хвилин.
4. Перевірити `/status` і повторно ввімкнути потрібні сповіщення.

Не передавайте код або токен у чат підтримки. Старий недійсний запис не відновлюється
автоматично: причиною невідповідності міг бути як вихід старої версії, так і зміна
пароля чи явне відкликання. Дійсні прив’язки перепідключати не потрібно.

## Перевірки

```bash
.venv/bin/python -m pytest -q tests/test_telegram_sessions.py tests/test_security.py tests/test_telegram.py tests/test_users.py tests/test_settings.py tests/test_telegram_controls.py
```

Тести використовують синтетичні SQLite, забороняють IP-сокети й підставляють
Telegram API. Перевіряються всі ролі, копія cookie після logout, два облікові
записи в одному браузері, перезапуск engine/dispatcher/бота, довга відсутність
вебсесії, незмінність налаштувань та строку коду, відкликання, конкурентна зміна
пароля, rollback і доступність сповіщень. Asyncio дозволено лише внутрішній
локальний socketpair; зовнішніх Telegram/Modbus-запитів немає.
Результат перевірок кількома пакетами: **305 різних Python-тестів пройшли**,
без xfailed. Після зміни читання авторизації повторно пройшов пакет із 126
перевірок Telegram, сесій і керування через mock.

## Погоджене застосування

Міграцій та нових залежностей немає. Перед оновленням зберегти перевірений SQLite
backup та попередній source/config snapshot; не відновлювати стару БД поверх нових
робочих даних. Зміни мають бути опубліковані в GitHub/main.
Для активації потрібен погоджений перезапуск **вебслужби й наявного бота**:

```bash
sudo systemctl restart ingecon-web.service ingecon-telegram.service
sudo systemctl is-active ingecon-web.service ingecon-telegram.service
```

Вебобробник атомарно підтримує сумісні версії записів, бот читає їх одним запитом.
Перезапускається лише існуюча служба, без другого екземпляра
polling. Збережені ключі, токен і Telegram-прив’язки не замінюються; міграція
даних не виконується. Для відкату повернути попередній source snapshot і
погоджено перезапустити ті самі служби. Відкат коду не потребує відновлення БД.
Стара версія знову відкликатиме Telegram при наступному logout.
