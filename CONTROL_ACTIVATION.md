# Керування INGECON SUN 3Play 100 TL для випробування

Власник явно дозволив керування **всіма зареєстрованими 100TL**, включно з
пристроями цієї моделі, доданими пізніше. Це дозвіл на тестування, а не
підтвердження сумісності прошивки. Невідомі моделі не допускаються.
Без приватного файла дозволу команди вимкнені. Саме встановлення коду нічого
не вмикає і жодної команди інвертору не надсилає.

## Командний профіль

Джерело: специфікація Ingeteam **AAA0030IMB03_K**, 23.05.2022,
§2.1.1–2.1.2, §2.2.2–2.2.4, стор.3–5, 8, 11, 13.
Доступна [копія документа виробника](https://www.scribd.com/document/928481096/Ingeteam-et112).
Номер прошивки обладнання не наданий; застосовність потребує перевірки.

| Дія | Запит | Адреса PDU | Слова |
|---|---|---|---|
| Увімкнути | FC06 | 1000 | `[6]` |
| Вимкнути | FC06 | 1000 | `[5]` |
| Ліміт P, 1–100 % | FC16 | 1000–1001 | `[3, floor(P × 32767 / 100)]` |
| Повернути максимум | FC16 | 1000–1001 | `[3, 32767]` |

Дані й команда ліміту передаються **одним** FC16. Порт і Unit ID беруться
з `MonitorConfig` конкретного інвертора; за відсутності запису — з глобальних
транспортних початкових значень. Таймаут 2 с, retries=0.
Це фіксований спільний профіль `ingecon_3play_test_v1`.
Редагована історична карта `modbus.json` не є активною картою цього профілю.
Історичний HR46 і довільні записи через `modbus_utils` залишаються заблокованими.
FC04-моніторинг 20–35/52–54 не змінено.

## Вебпанель і Telegram

Administrator та Operator можуть вибрати інвертори на головній сторінці
і натиснути «Увімкнути», «Вимкнути», «Застосувати ліміт» або «Максимум».
Є також **Керування Modbus** (`/settings/modbus/control`). Viewer керувати не може.
Потрібні авторизація, CSRF і окреме одноразове підтвердження на 120 секунд.
Зміна IP, моделі, порту, Unit ID, користувача, ролі, конфігурації чи дозволу
анулює підготовлену команду. У вебгрупі максимум 100 інверторів.
Уся група проходить перевірку до першого запису.

У Telegram: `/control` → інвертор/група → Start/Stop або кнопки 25/50/75/100 %.
Довільний цілий відсоток: `/limit ID ВІДСОТОК`, наприклад `/limit 1 37`.
Команда лише готує підтвердження; без другого натискання запису немає.
У Telegram-групі максимум 10 пристроїв. Збережені прив’язки та ролі діють
без повторного налаштування. Старий per-device файл Telegram не потрібний
для цього спільного дозволу і не змінює карту виконання.

Веб і бот використовують `commands.execute_devices` та один endpoint-lock
з монітором, включно з різними Unit ID одного шлюзу. Кожна команда має
аудит автора, джерела, часу, цілі, транспортних параметрів, слів і результату.
`processing` фіксується до I/O. Повторне підтвердження не повторює операцію;
збій збереження кінцевого аудиту не повідомляє успіх.

Позитивна відповідь FC06/FC16 підтверджує прийняття запиту пристроєм.
Для сумісності результат API називається `register_confirmed`, але це
**не підтвердження фізичного запуску, зупинки або досягнутого ліміту**.
Перевірте наступні FC04-показники стану та ліміту. Немає автоматичних повторів,
очікування підключення до мережі або підміни стану в БД після команди.
При втраті відповіді спочатку перевірте стан обладнання.
Панель довільних регістрів завжди блокує FC06/FC16, навіть коли керування ввімкнене.

## Застосування на сервері

Міграція та встановлення пакетів не потрібні. Не редагуйте секрети або SQLite.
До активації перевірте чисту `main`, тести та наявність точного commit на GitHub.
Від користувача `codex` підготуйте backup, підставивши SHA нового commit
і попередньої робочої версії:

```bash
cd /opt/ingecon-control
.venv/bin/python -m deploy.discovery_release prepare --expected-sha НОВИЙ_SHA --previous-sha ПОПЕРЕДНІЙ_SHA
```

Помічник робить SQLite backup, перевіряє відновлення в окремий файл,
зберігає захищену конфігурацію й попередній source snapshot.
Його назва та префікс каталогу `discovery-` збережені для сумісності;
пошук мережі він не запускає.
З отриманим абсолютним шляхом `manifest.json` виконайте **від root**:

```bash
bash /opt/ingecon-control/deploy/activate_controls.sh /АБСОЛЮТНИЙ/ШЛЯХ/manifest.json
```

Скрипт перевіряє опублікований SHA, backup і стан служб, зберігає unit-файли,
створює приватний файл `instance/production/inverter-controls.json` (0600,
власник codex), перезапускає лише `ingecon-web` та єдиний `ingecon-telegram`.
Наявний дозвіл або systemd drop-ins він не перезаписує.
Перевірки: HTTP login/CSRF/ролі, активні кнопки, доступність пошуку, інвентар,
heartbeat та один Telegram poller (`getMe`, без повідомлень).
Фізичних команд ці перевірки не виконують.
При помилці активації дозвіл вимикається, а веб і бот запускаються з
попереднього snapshot через явно позначені `92-controls-rollback.conf`.
SQLite назад не відновлюється; інші служби та мережеві правила не змінюються.
Невдалий відкат явно повідомляється; guards не обходяться.
Після успішної перевірки оформіть і опублікуйте annotated production release tag.

Аварійне відкликання дозволу без фізичних команд, від `codex`:

```bash
cd /opt/ingecon-control
.venv/bin/python -m inverter_controls --disable
```

Backend перевіряє дозвіл перед кожною командою. Для оновлення кнопок та меню
після зміни дозволу перезапустіть веб/бот від root.
Для окремого погодженого ввімкнення конфігурації (без перезапуску):

```bash
.venv/bin/python -m inverter_controls --enable-all-100tl --accept-unverified-firmware
```

Це локальний адміністративний CLI, недоступний через HTTP. Пошкоджений,
сторонній, незахищений файл, symlink або невідомі поля відхиляються.
Runtime-дозвіл, backup, БД і секрети не потрапляють до Git.

## Перевірки без обладнання

```bash
.venv/bin/python -m pytest -q
node tests/js/dashboard.test.cjs
node tests/js/panel.test.cjs
node tests/js/discovery.test.cjs
bash -n deploy/activate_controls.sh
```

Усі control-тести використовують in-memory Modbus і mock Telegram API;
IP-сокети, DNS і запуск зовнішніх процесів заблоковані тестовою фікстурою.
Приватний дозвіл тестів створюється тільки в pytest tmp_path.
