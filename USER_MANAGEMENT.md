# Користувачі порталу

Керування доступне лише користувачам із роллю **Administrator**:
у верхній навігації виберіть **Налаштування → Користувачі** (`/settings/users`).
Поруч розташована окрема вкладка **Telegram** (`/settings/telegram`). Operator і Viewer
бачать лише вкладку Telegram й отримують 403 при прямому зверненні до користувачів. Без входу — 401.
Публічної реєстрації немає.
Старі URL `/users` і `/telegram` збережено для закладок та відкритих форм;
вони показують ті самі вкладки з тими самими перевірками доступу й CSRF.

## Додавання

1. Натисніть **Додати користувача**.
2. Введіть унікальне ім’я: 1–64 символи `a-z`, `0-9`, `_`, `.`, `-`.
   Пробіли по краях видаляються, літери зберігаються в нижньому регістрі.
3. Виберіть Administrator, Operator або Viewer. За замовчуванням — Viewer.
4. Введіть і повторіть пароль від 12 до 1024 символів.
5. Натисніть **Створити користувача**. Після успішного збереження відкриється список.

Administrator керує користувачами та налаштуваннями інверторів;
Operator має моніторинг і дозволені операції; Viewer має лише перегляд.
Надання ролі **не вмикає Modbus writes**. Паролі зберігаються як scrypt-хеші;
паролі й хеші не повертаються до HTML, зокрема при помилці форми.

Першого адміністратора, коли входити ще нікому, створюють наявною
інтерактивною CLI-командою за [SECURITY.md](SECURITY.md).
Стандартні облікові записи та паролі не створюються.

## Видалення

1. Біля потрібного облікового запису натисніть **Видалити**.
2. На окремій сторінці перевірте ім’я та роль і введіть точне ім’я користувача.
3. Натисніть **Підтвердити видалення** протягом двох хвилин.

GET відкриває лише підтвердження. Зміни виконує POST із CSRF та окремим
підписаним підтвердженням, прив’язаним до адміністратора і поточного запису.
Зміна даних користувача, пароля або версії сесії робить підтвердження недійсним.
Власний обліковий запис і останнього активного адміністратора видаляти не можна.
Перевірка прав повторюється після отримання SQLite write lock.

Видалення відкликає вебсесії, Telegram-прив’язку, невикористані коди та очікувані
Telegram-команди **лише цього користувача**. Його очікувані сповіщення позначаються
як пропущені. Повідомлення, яке бот уже передав на відправлення, відкликати
неможливо. Решта користувачів і Telegram-прив’язок зберігаються.
Історія станів інверторів, завершені доставки та аудит не видаляються.
Дія незворотна: повторне створення імені означає новий обліковий запис.

SQLite може повторно видати видалений числовий ID. Нові облікові записи
отримують випадкове початкове значення `session_version`, щоб старі підписані
cookie не відновили доступ після повторного використання ID. Існуючі версії
сесій і паролі не змінюються при завантаженні нового коду.

У наявній таблиці `command_audit` зберігаються події `user_create` і `user_delete`:
адміністратор, час, цільова роль та ім’я, результат. Паролів і токенів там немає.
Схема БД не змінюється, міграція та `init-db` для цього оновлення не потрібні.

## Застосування і тести

Підготовка коду не змінює production SQLite, stewe, секрети, служби або мережу.
Операції над production-обліковими записами виконає сам адміністратор через
панель після завантаження нового коду. Збережіть штатну резервну копію перед
фактичним адмініструванням доступу. Не створюйте тестових користувачів у
production для автоматизованих перевірок.

Щоб нові маршрути з’явилися у вже працюючій панелі, потрібен погоджений
перезапуск лише наявної вебслужби. Цей крок автоматично не виконується:

```bash
systemctl restart ingecon-web.service
systemctl is-active ingecon-web.service
```

Telegram, Nginx, firewall, SSH і Tailscale для цього оновлення не перезапускають.
Додаткових пакетів чи налаштувань systemd не потрібно. Після перезапуску
Усі ролі бачать пункт **Налаштування**; вкладка **Користувачі** доступна лише Administrator.

Автоматичні тести використовують синтетичні SQLite та блокують фізичну мережу:

```bash
.venv/bin/python -m pytest -q tests/test_users.py
.venv/bin/python -m pytest -q
node tests/js/dashboard.test.cjs
node tests/js/panel.test.cjs
```

Покрито ролі, CSRF, валідацію, дублікати, хешування, вхід нових користувачів,
підтвердження та його строк, відкликання Telegram/вебдоступу, повторне використання
ID, атомарний rollback, незмінність чужих прив’язок та історії.
